## 8.5 ★ 追加实验一：机制臂的**跨家族复现**（enum / locate / enumAbstain）

E2 的机制结论是"**门是 abstain 词位，不是'要求逐项枚举'**"。把它在新家族上重跑一遍
（同一仪器 19e；`enum` = 要求逐人枚举但只暴露数字字段，`locate` = 要求定位但只暴露数字字段，
`enumAbstain` = **同一**枚举要求 **加**一个 abstain 词位）。**在共同 item 集合上比比率**
（E2 的 `base` 文件是多轮追加的，如 32B/st_a 有 412 行，拿计数比会把分母差异误读成机制差异）：

| 家族 | 域 | 共同 n | `base` | `enum` | `locate` | `enumAbstain` |
|---|---|---|---|---|---|---|
| Gemma-3-12B | VisDrone | 150 | 0.033 | **0.387** | 0.087 | **0.000**（120 弃答） |
| InternVL3.5-8B | VisDrone | 150 | 0.633 | 0.593 | 0.753 | **0.000**（136） |
| Phi-3.5-Vision | VisDrone | 150 | 0.613 | 0.233 | 0.847 | **0.000**（150） |
| Qwen3-VL-32B-AWQ（锚） | st_a | 103 | 0.990 | 0.893 | 0.961 | **0.000**（103） |
| Qwen3-VL-32B-AWQ（锚） | ucf | 180 | 0.922 | 0.883 | 0.861 | **0.000**（180） |
| Qwen3-VL-32B-AWQ（锚） | VisDrone | 273 | 0.982 | 0.945 | 0.963 | **0.015**（268） |
| Qwen3-VL-32B-AWQ（锚） | AI-TOD | 154 | 0.968 | 0.883 | 0.883 | **0.097**（133）← 唯一例外 |

**读数（跨家族）**：
1. **只给数字字段时，要求枚举/定位并不能消除零**：`enum` 与 `locate` 的答 0 率仍在
   **23.3%–89.3%**（Gemma/InternVL3.5/Phi/Qwen 三域）；Qwen-32B 在密集域 `enum` 后仍有 89.3%/88.3%。
2. **同一提示词只加一个 abstain 词位，零即消失**：`enumAbstain` 在 **6/7 个单元格 ≤1.5%**，
   唯一例外是 E2 已记录的 Qwen-32B/AI-TOD（9.7%）。
3. ★ **新发现（机制的方向性）**：**"要求逐项枚举"会把零率推高**——Gemma 在 VisDrone
   从 3.3% 升到 **38.7%**，InternVL3.5/Phi 在密集域 `locate` 从 0.7%/0.0% 升到 **29–32%**。
   即：枚举压力**制造**了"无法确证"的状态，而 abstain 词位把这个状态**导出**为显式弃答。
   这比 E2 的原始表述更精确：契约决定**出口**，枚举压力决定**有多少经验落在出口前**。

**判据声明（必须写进记录）**：本节的"三条腿"判据（`enumAbstain ≤5%`、`enum ≥5%`、
`enum/base ≥0.25`）是**事后自订**的读数规则，**不在**冻结判据 `a5_criteria_frozen.json` 之内
（冻结判据只覆盖 base/permit/channel 三臂）。故此处只报表与例外，不宣称预注册。

## 8.6 ★ 追加实验二：尺度与模板的**中性化**（消融）

用**独立仪器** `19f_probe_ablation.py`（由 19e 派生，`make_19f.py` 断言 19e 字节未变；变体 =

**为什么第一批把变体放在 Gemma 的密集域是无效的**：Gemma 密集域 base 答 0 = **0.000**，

**60.2%**，与 §M.18.3 记录的 **62.1%** 一致（相差 1.9 pp，抽样不同）。

1. **输入尺度对零率几乎无影响**：四个域内 Δ ≤ **0.7 pp**（压缩到 640 或放大到 1536 都一样）。

2. ★ **模板不是无关变量，且是家族依赖的**：一条 system 消息把 **Phi-3.5 的 VisDrone 零率

3. **契约效应在所有变体下都不变**：三个家族、四种变体、共 12 个变体单元里，
   `permit` 臂的"仍答 0"**一律为 0**。⇒ **被消融动摇的是零率，不是契约门控**。

**确定性**（同条件 reps=3，独立目录）：Gemma/st_a 前 60 项，`base` 与 `permit` 两臂
**三次全同 60/60**；`native` 变体与主跑的**类别一致率 1.000**（Gemma）。

## 8.7 ★ 追加实验三：构建轴（同权重换构建）——**部分成立，边界已写清**

目标：把"密集域答 0 绑定具体构建"从 Qwen 血统拓到**新血统**上。

| 手段 | 结果 |
|---|---|
| `--quantization fp8`（在线 FP8） | ✗ 引擎核心初始化失败（A800 = `sm_80`，无 FP8 kernel） |
| `--dtype float16` | ✗ `model type 'gemma3' does not support float16`（数值不稳定） |
| `pip install bitsandbytes` + `--quantization bitsandbytes` | ✗ vLLM 0.29 的量化方法表里没有该项 |
| **`--quantization int8_per_channel_weight_only`** | **✓ 可用**（W8A16 在线权重量化，180 s 起服） |
| 下载官方 4bit AWQ/GPTQ 构建 | ✗ 本轮未取到（HF/hf-mirror API 401；本地只读缓存里这四个家族无量化版） |

**int8（W8A16）与 BF16 的对照**（同一 Gemma-3-12B 权重、同提示词、同 item）：

| 域 | BF16（未量化） base 零率 | int8 权重再量化 base 零率 | permit 仍答 0 |
|---|---|---|---|
| st_a（密集） | 0.000（0/103） | 0.000（0/103） | 0/0 |
| ucf（密集） | 0.000（0/150） | 0.000（0/150） | 0/0 |
| VisDrone（航拍） | 0.032（5/158） | 0.033（5/150） | **0/5（两者都是 0）** |

**读数（诚实版）**：
- **8bit 权重再量化不会在一个本来不出零的家族里"造出"密集域答 0**（0.000 → 0.000）；
- 但把 Qwen-32B 的密集域零率推动 **81.3 pp** 的那次变化，是**在 4bit/8bit/GPTQ/FP8/BF16 构建之间**发生的；
  **8bit 在线再量化 ≠ 官方 4bit 构建**，二者不可混为一谈；
- 因此"构建轴"在**新血统**上只做到**部分**证据：**"换构建不改一个无零家族"成立，
  "某新家族存在一个会出零的 4bit 构建"本轮未取到**（原因已列，属环境限制而非"不存在"）。
- 契约效应在该构建下同样成立（`permit` 仍答 0 = 0/5）。

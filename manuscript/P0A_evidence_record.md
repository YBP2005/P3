## 0 一句话结论

**同一构建、同一批 253 项密集图、同一仪器、同一服务配置，只把提示词从中文换成英文**：密集零池的
**答零率 9.88% → 0.40%**（25 项 → 1 项），而**数值答案从 250 项掉到 156 项**——EN 臂**不再给数字**，

⇒ 语言轴**不制造也不消除弃答通道**，它决定通道**以哪种形式露出**；这正好把 §5.5 与标题里
"one anchor build **and language**" 的限定语从"作者声明的适用范围"变成**有实测支撑的适用范围**。

## 3 ★★ C3 语言读数（本轮最重的一条）与**两口径纪律**

| 密集零池（253 项），start 1 | 答零 /253 | 答零 /已答 | 弃答 |
|---|---|---|---|
| 中文 `base`（本轮） | **25 = 9.88%** | 25/250 = 10.00% | 3 = 1.19% |
| 中文 `base`（存档起点，§M.19.17） | 24 = 9.49% | **24/251 = 9.56%** | 2 = 0.79% |
| **英文 `base`（本轮）** | **1 = 0.40%** | 1/156 = 0.64% | **97 = 38.34%** |

**★ 弃答率必须并列两个口径**（这是**词表覆盖差**，不是"类型 vs 措辞"）：

* **(i) 放行分析器三词表口径**（`abstain` / `cannot_judge` / `no_people`）：EN 密集零池 = **0/253 = 0.00%**
  —— **97 行一个都认不出**；中文那 3 行（`无法准确数出`）同样认不出。
* **(ii) 宽口径**（类型优先 + 宽词表兜底，`env/_p0a_cls.py`）：**97/253 = 38.34%**
  —— 95 行**散文弃答**（`unable to count`，**无 `count` 字段、无任何数字**）+ 2 行 `count` 字符串（`"large crowd"`）。

**★ 与口径无关的那一条（最关键）**：本仪器 `parse_ok=0` **等价于"整段回复里没有任何数字"**——
`pf_p0_probe.py::parse()`（L34–L41）在 `count` 键不中时**回退搜 `-?\d+`**。故那 95 行**在任何词表、任何判读下
都不是数值答案**。⇒ "**EN 臂不再给数字**"（数值答案 250 → 156、答零 25 → 1）是**口径无关**的结论。

## 4 阳性对照：**按字面未复现（FAIL）**，如实记录、不回改判据

| 项 | 本轮 start1 重跑 | 存档起点 |
|---|---|---|
| 行数 | 253 | 253 |
| 数值答案 / 弃答 / 真空 | 250 / 3 / 0 | 251 / 2 / 0 |
| 答零 | **25 = 9.88%**（9.49% of 253、10.00% of 250） | **24/251 = 9.56%** |
| Wilson 95% | [6.78, 14.18] | [6.46, 13.73] |
| 逐项完全一致 | **239/253 = 94.47%**（13 项取值 + 1 项类型） | — |
| 答案类型一致 | **252/253 = 99.60%** | — |

**预注册要求"复现 24/251"，按字面未达成 ⇒ 记为 FAIL**（事后放宽 = 移动球门）。可读的上下文是：

1. **存档那一行本身就是三起服之一，而三起服自身就是 24 / 21 / 23 of 251 = 9.56 / 8.37 / 9.16%**——
   同一仪器、同一几何、三次全新起服，答零数就跨了 **1.19 pp**；本次只比其最大值高 **+0.32 pp**。
2. 该差落在论文**自印的 across-repeat 带 2.15–6.46 pp** 之内，两侧 Wilson 区间大幅重叠。
3. 差异**全是单档邻近翻转**（500↔300、1000↔0、250↔256…），无任何系统性偏移。

⇒ 结论口径：**仪器同一性成立（同提示词、同服务配置、同代码路径、同图；聚合率与差异形态都在该仪器自身的
起服间变化之内）；预注册的"逐位一致"措辞过严，该项如实记为未复现。**
**两条禁令**：**不并池**、**不用本次重跑替换或回填放行值**；本对照只作仪器同一性证据，**不参与 C1–C5**。
附录 3 另立"以后阳性对照怎么判"的三条判据（类型一致率 / 聚合率是否在该仪器自身起服间跨度内 / 差异分布形态），
并**明写只对 20261002 之后新发起的运行生效**。

## 6 本轮踩到并已登记的两条

* **`parse_ok` 的语义**：本仪器把"弃答"与"无法解析"**编码成同一个 `parse_ok=0`**（根因：`parse()` 的正则
  `\{\s*count` **不容引号**，而弃答输出是 `{"count": "abstain"}`）。⇒ 任何"`parse_ok` 率 <95% 即不合格"的
  判据在本仪器上必须改成**双口径**，5% 阈值用于**真·格式失败率**。
* **运行时吞吐**：实测 **≈50 项/分钟**（253 项约 5 分钟），7,712 次调用合计 **2 h 50 min**。慢因是**大图 prefill**
  （vLLM 日志：`Running: 4 reqs, Waiting: 0 reqs` 恒定、KV 占用仅 13–24%、prompt 吞吐 1,400–2,200 tok/s、
  generation ≈10 tok/s、单请求中位 4.99 s；图 1024×704/768）——**不是排队、不是解码**。
  `workers=4`/`gmem` 属冻结仪器参数，**中途未改**；该吞吐值只作**仪器测量**留档，不进入任何合格判定。

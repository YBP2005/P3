## A. 意见 A3："跨度可能只是**旋钮扫描网格**与**输出量纲**的函数"

评审原话（要点）："检测 τ 扫 177 点、prompt 扫 7 级、tiling 扫 6 级，跨度天然随扫描密度与端点选取增长。
检验：对每个旋钮在**相同点数、相同分位栅格**下重算跨度（子采样到 min 点数），看排序是否保持；
判据是 knob 排序的 Spearman ≥ 0.8；若崩塌，'response spectrum' 须改为 endpoint sensitivity report。"

### A.1 做法（`analysis/work/span_equalcount.py`）

1. **重建 24 个单元的逐档 ρ 阶梯**（池化 ρ = (Σpred−Σgt)/Σgt，异常值 `pred ≥ 1e5` 剔除，
   同一单元各档取**同一 item 交集**，保证档间可比）：

| 旋钮 | 来源文件 | 档数 |
|---|---|---|
| 检测 τ（域内 / COCO × 3 个 imgsz） | `analysis/data/threeway_curves_v2.csv` | 16 / 32 |
| 密度回归·输入尺度（mult / short × st_a,ucf） | `analysis/data/threeway_curves.csv` | 6 / 4 |
| VLM·像素预算（res_ctrl 逐图 + threeway 两套） | `pod_mirror/res_ctrl__{q32,ivl}/res_ctrl_<ds>.csv`、`threeway_curves.csv` | 5 |
| VLM·提示词族 V1–V5 | `pod_mirror/dense_prompt_results/*_V{1..5}_*.csv`（含 ivl） | 5 |
| VLM·切块级别 tile2–tile6 | `pod_mirror/tile_results/*_tile*.csv` | 5 |
| VLM·输出契约（E2 六臂） | `analysis/e2_newh20/e1_qwen3-vl-32b-awq_<ds>_{base..channel}.csv` | 6 |

2. **等点数子采样**：全部阶梯按分位位置降到 **k = 4**（全局最少档数），重算跨度。
3. **端点扰动**：分别剔除最高档 / 最低档后重算跨度。
4. 与全长阶梯的排序做 **Spearman 秩相关**（并列取平均秩）。

### A.2 结果（冻结于 `analysis/work/span_equalcount_result.json`）

**排序稳健 —— 评审的判据通过：**

| 对照 | Spearman（24 单元） | 判据 |
|---|---|---|
| 全长 vs **等点数(k=4)** | **0.964** | ≥0.8 ✓ |
| 全长 vs **剔除最高档** | **0.977** | ≥0.8 ✓ |
| 全长 vs **剔除最低档** | **0.993** | ≥0.8 ✓ |

**量级不稳，且方向明确（细网格旋钮被"扫描密度"抬高了）：**

| 单元 | 档数 | 全长跨度 | 等 k 跨度 | 保留率 |
|---|---|---|---|---|
| 检测·域内 / VisDrone / tau@1536 | 16 | 593.7 | **258.2** | 0.43 |
| 检测·域内 / VisDrone / tau@1024 | 16 | 515.4 | **231.9** | 0.45 |
| 检测·域内 / VisDrone / tau@640 | 16 | 407.5 | **182.1** | 0.45 |
| 检测·COCO / VisDrone / tau@1536 | 32 | 175.8 | **35.6** | 0.20 |
| 检测·COCO / VisDrone / tau@1024 | 32 | 116.8 | **16.7** | 0.14 |
| 检测·COCO / VisDrone / tau@640 | 32 | 84.0 | **8.4** | 0.10 |
| 密度·st_a / mult | 6 | 1432.9 | 1432.9 | 1.00 |
| 切块 / st_a | 5 | 33.3 | 33.3 | 1.00 |
| 像素预算 / q32 / visdrone | 5 | 14.6 | 14.6 | 1.00 |

- 等点数后跨度中位保留率 **1.00**（多数单元本就只有 4–6 档）；细网格的 **τ 单元降 2.2–10 倍**
  （域内 2.2–2.3×；零样本 COCO 5–10×）。
- 剔除单个端点后，中位变化 0%，最坏单元（密度·st_a / mult）损失 **53%** —— 与附录 F.8 的
  "端点贡献 54–80%" 一致。

### A.3 落到稿子里的两句话（已写入 §7.3 与附录 F.10/F.11）

1. **排序**是主张的载体（Spearman 0.964–0.993 ⇒ 谱不是网格设计的函数）；
2. **跨旋钮比量级必须带网格密度**：等点数后零样本 COCO 的 τ 单元落到 8–36 pp，
   **低于**切块（33–40 pp）、**远低于**域内 τ；端点退化的阶梯按"端点受限"读。

### A.4 仍未做的对照（如实登记）

- **输出量纲对照**（评审的另一半意见）：VLM 输出整数计数、密度回归输出连续积分、检测输出 box 数，
  `forbid0` 之所以最强可能只是"整数输出禁 0 后只能跳到大整数"。
  本轮**未做**——它需要**新的推理**（对 tiling 子计数保留小数、或量纲匹配的合成栅格对照），
  超出"纯 ANALYSIS"的范围，留给作者决定是否补跑。

## B. 意见 A5-实验 1 / §8.2："头条量可能只是**构建**的属性，不是任务的属性"

评审原话（要点）："判据是'答 0 份额'的构建内/构建间方差分解；预期构建效应在密集域占主导、
域效应在航拍占主导；若构建间方差 ≥ 域间方差，标题须加 configuration-specific 限定。"

### B.1 做法（`analysis/work/variance_decomp.py`）

**平衡 5×4 设计**：因子 A = Qwen3-VL-32B 的 **5 个部署**（AWQ-4bit / AWQ-8bit / BF16 / FP8 / GPTQ-W4
—— 同一份权重的五种量化构建，故构建效应**不含"换了模型"**）；因子 B = 4 个域
（st_a / ucf / visdrone / aitod）。因变量 = 零池 base 臂**答 0 率**；公共 item 子集
st_a 103 / ucf 180 / visdrone 150 / aitod 150，**跨构建完全一致**。

### B.2 结果（冻结于 `analysis/work/variance_decomp_result.json`）

| 构建 | st_a | ucf | VisDrone | AI-TOD |
|---|---|---|---|---|
| AWQ-4bit | 99.0 | 92.2 | 99.3 | 97.3 |
| AWQ-8bit | 65.0 | 69.4 | 97.3 | 92.7 |
| BF16 | 62.1 | 66.7 | 97.3 | 93.3 |
| FP8 | 79.6 | 79.4 | 97.3 | 92.7 |
| GPTQ-W4 | 8.7 | 16.1 | 96.7 | 88.7 |

两因素平方和分解：**域 38.7% / 构建 33.9% / 交互+残差 27.4%**。

- **密集域内构建占主导**：同一 checkpoint 的五个部署在 st_a 相差 **90.3 pp**（8.7→99.0）、
  在 ucf 相差 **76.1 pp**（16.1→92.2）。
- **航拍域内构建几乎不起作用**：VisDrone **2.7 pp**（96.7→99.3）、AI-TOD **8.7 pp**（88.7→97.3）。
- **同一构建跨域**：GPTQ-W4 **87.9 pp**、BF16 35.2 pp，而 AWQ-4bit 只 7.1 pp（因为它在各域都已 92–99%，饱和）。

### B.3 判定与措辞

- 评审判据"构建间方差 ≥ 域间方差 ⇒ 须加 configuration-specific 限定"：**33.9% < 38.7%，严格说不成立**。
- 但**交互项占 27.4%**，且真结构是"**域定基调、构建定密集域的细节**"：
  ⇒ 正确措辞是**同时**说两件事（已写入 §9 与 §5.7）：**密集域的头条是构建特异的，
  航拍域的头条是任务/域特异的**；频率性主张一律限定在"所测配置与构建之内"。
- 这也把 §11.2 的"两类答 0"从定性升级为**定量**（90.3 pp vs 2.7–8.7 pp）。
